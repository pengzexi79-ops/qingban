# AI 任务模板

## 修改完成后最短调用

成员已经完成一轮修改，只需告诉 AI：

```text
使用 $qinban-team-collaboration，根据我当前实际 Git 改动生成本轮开发保存点档案。沿用本任务已经声明的角色、成员和任务编号；不要追加实现，不要 commit 或 push。
```

如果是本 AI 任务内连续开发，首次声明身份和任务编号后，后续每轮修改由 AI 自动执行，不必重复发送这句话。

## 前端成员直接复制

```text
使用仓库中的 $qinban-team-collaboration。

任务编号：QB-____-___
产品负责人：总指导
我的执行角色：frontend-core / frontend-chat / frontend-experience
负责人：我的 GitHub 用户名
产品目标：
验收标准：
明确不做：
允许修改：
禁止修改：
接口影响：无 / 需要后端定义 / 已由后端冻结
依赖任务：
热点文件认领：
技术负责人确认：待确认 / 已确认

团队规则：总指导决定产品方向，backend-lead 决定技术方案并最终审核代码。即使我是总指导本人参与前端开发，也不绕过技术审核。

要求：
1. 先读取 AGENTS.md 和协同 Skill，不要立即改代码。
2. 先报告当前分支、角色边界、计划修改文件、接口依赖和并行冲突。
3. 技术负责人未确认时，只能分析和出方案，不改代码。
4. 只在独立任务分支开发，不直接修改或推送 master。
5. 不跨角色顺手改代码，不自行改框架、依赖、API、数据库或后端。
6. 每完成一轮有意义的修改，在向我汇报前自动读取 Git diff，并运行 Skill 的存档脚本生成新的保存点档案。
7. 完成后列出修改文件、存档路径、测试、接口影响、风险和需要 backend-lead 审核的内容。
8. 未经我明确要求，不要 commit、push、创建 PR 或修改 GitHub 设置。
```
