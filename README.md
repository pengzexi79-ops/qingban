# 亲伴 QinBan

> 把重要的陪伴，放在身边。

亲伴是一个面向情感陪伴场景的 **Vue 3 前端产品原型**。当前阶段的目标不是伪装成已经完成的 AI 平台，而是先把页面架构、显示布局、交互状态和后端所需的数据字段做完整，供产品审核和后端团队继续接入。

**当前版本：`0.4.0-frontend`（2026-09-03）**

## 当前范围

- 只实现前端页面和本地模拟交互。
- 数据保存在浏览器 `localStorage`，没有真实账号、数据库、向量库和云端同步。
- 主动消息、多 AI 群聊、朋友圈自动发布、长期记忆检索和多模态能力均为前端演示或配置占位。
- API 页面用于展示服务商、协议、模型和能力的配置结构；正式产品必须由后端代理请求并安全保管密钥。
- 不包含参考图片中的 QQ、客服、赞助者等外部联系方式。
- 不实现强制锁屏、读取设备使用情况、设备控制等高风险功能。

## 已有页面与交互

### 会话与通讯录

- 微信式会话首页、好友/群聊混合列表、搜索、未读和类型筛选。
- 桌面端会话双栏，移动端独立聊天页。
- 聊天记录只在应用内部滚动，输入区保持在页面底部；消息输入限制 500 字。
- AI 通讯录支持搜索、分类、能力标签、记忆数量和主动消息状态。
- 每位 AI 可上传独立头像，也可使用文字头像和主题色。

### AI 好友配置

- 基础资料、关系、人设、性格、语言风格、边界和禁用内容。
- 长期记忆模式、总结方式、时间范围、召回阈值和最大条数。
- Markdown、流式输出、输入状态、分段消息、回复延时和气泡风格。
- 主动陪伴时间段、频率、最小/最大间隔、每日上限和忙碌时间规避。
- 听觉、语音、声音复刻、视觉、视频、文生图和联网能力开关。
- 每位 AI 可绑定不同的 API 配置。

### AI 群聊

- 创建/编辑群聊、自定义群头像、从通讯录选择多个 AI。
- 随机或顺序发言、成员排序、冷却时间和每轮最多发言数。
- 可触发一轮多 AI 前端模拟回复，真实调度等待后端接入。

### 长期记忆与数据台

- 长期记忆新增、编辑、删除和类型展示。
- 用户偏好、关系事件、关系记忆、对话摘要统一数据结构。
- 向量集合、Embedding 模型、维度、Top K、相似度阈值和模拟召回结果。
- 页面内展示 `MemoryRecord` 字段、接口契约 JSON 和后端处理链路。

### AI 朋友圈

- 动态信息流、用户发布、AI 主动发布模拟。
- 点赞、评论、收藏、可见范围和图片占位。
- 展示 AI 主动发布频率，真实定时发布与内容生成等待后端实现。

### 我的与设置

- 用户头像、昵称、签名、用户画像、收藏、开发团队、用户协议和更新说明。
- 多套 API 配置，包含国内、国外、本地和自定义服务商入口。
- Base URL、API Key、协议类型及对话/视觉/听觉/TTS/声音复刻/视频/文生图模型字段。
- 模型识别按钮：浏览器条件允许时读取 `/models`，否则显示明确标注的示例模型目录。
- 全局能力开关、浅色/深色主题、字体、气泡圆角、消息间距和高级请求参数。
- API 消耗诊断页展示 Token、费用、上下文、记忆、人设、群聊和能力开销的前端估算。
- 本地数据导出、导入、恢复和清空；导出时自动移除 API Key。

## 技术实现

- **Vue 3 Production CDN**：无构建步骤，便于团队快速查看和继续迁移。
- **原生 CSS**：固定视口应用壳、页面内部滚动、桌面/移动响应式布局和深色主题。
- **原生 JavaScript**：页面状态、模拟交互、头像压缩、数据导入导出。
- **localStorage**：本地键名为 `qinban_frontend_v4`，兼容读取原品牌的 `qingban_frontend_v4/v3/v2` 演示数据。

当前保留 CDN 架构是为了先完成产品页面，不做无收益的框架重写。进入正式工程阶段后，可在保持页面信息架构和数据模型的前提下迁移至 Vite + Vue 3 或 React。

## D 盘本地运行

```powershell
Set-Location D:\codex\qingban
python -m http.server 8765
```

浏览器访问：`http://localhost:8765/`

页面依赖 Vue CDN，首次加载需要能够访问 CDN。项目本身不包含任何真实 API Key。

## 后端接入原则

1. 前端中的 `id`、`companionId`、`groupId`、`messageId`、`memoryId` 应由后端生成并稳定保存。
2. API Key 不应由正式前端长期保存；设置页提交到后端密钥仓库后，只返回脱敏状态。
3. 单聊和群聊统一采用可追踪的消息事件；群聊消息必须包含 `senderId`。
4. 长期记忆写入需要来源、重要度、索引状态和可删除性；向量检索结果需要 `score` 与 `traceId`。
5. 主动消息、主动朋友圈和多 AI 调度必须由后端任务系统执行，并遵守时间窗、频率、每日上限、免打扰和用户关闭状态。
6. 声音复刻、图像和视频等能力需要单独授权、审计、内容安全和撤销机制。
7. API 损耗页最终应读取后端真实用量，不使用当前前端估算作为账单。

更完整字段和建议接口见 [`docs/BACKEND_HANDOFF.md`](docs/BACKEND_HANDOFF.md)。

## 数据与隐私提示

当前原型适合产品评审和前后端对齐，不适合保存真实敏感信息。正式上线前至少需要：

- 登录、鉴权、租户隔离和设备会话管理。
- 数据加密、权限校验、审计日志、导出和彻底删除。
- API 密钥后端托管、调用限额、失败重试和供应商用量对账。
- 情感陪伴安全策略、危机内容处理、未成年人保护和用户依赖风险控制。
